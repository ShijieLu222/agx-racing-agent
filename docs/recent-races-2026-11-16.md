v5 的逻辑只要目标比当前速度高、电池非零、姿态正常，就倾向请求 attack。它没有进一步判断：普通动力是否已经足够、弯中是否还剩可用于加速的抓地力、速度计划是否正在下降。因而本次优先修复能量分配。

这是源码与回放共同支持的改进方向。**不能将 13.644 秒全部归因于电池，也不能声称修复后一定追回这些时间**；公开录像没有对手源码和本人全部决策输入，摩擦圆仍是控制近似。

### 4. 这两场不是进站或缺油输掉

00:34 双方都软胎换中胎、进站一次，通行及换胎各 35.7658 秒，相同。06:24 为湿地，双方都没有进站。本人两场剩油分别 10.3138、9.7373 kg，没有缺油证据。

## v6 实际改动

- 把所需轮端力与 neutral、balanced 可提供的力比较：低档已经足够时不请求更高 ERS 档。
- 结合当前质量、下压力、实际横向 g 和道路曲率，估计纵向抓地余量。弯中负荷高时选择 balanced 或 neutral，出弯负荷释放后可立即恢复 attack。
- 速度包络正在下降、即将需要减速时，不继续请求额外助推；制动始终优先。
- 不添加固定最高速度、油门压制、电量保留线或恢复等待；孤立滑移标志不造成持续降速。转向、超车、进站和车辆设计保留现有实现。

该改动目标是减少低收益的能量部署，不保证任何位置都比 v5 更快。由于缺少完整 AGX 物理引擎，正式效果必须用新比赛确认。

## 检查、包与验证边界

- **85 项测试通过**，包含新增 ERS 选择、出弯立即恢复、制动优先，以及回放损坏/缺帧检查。旧测试中的小动力需求断言调整为无需 attack；原有速度误差滞回测试改用确实需要额外动力的夹具。
- **30,000 次合成调用：0 异常、0 非法动作**；act CPU 4.186 秒、p99 0.172 ms、最大 0.561 ms。本机 Python 3.13.3，不含序列化和平台开销；不能与先前不同运行环境的耗时直接比较。
- 三条赛道的简化单轨模型均完成一圈、未越过道路边缘。模型没有真实轮胎、能量消耗或交通，不将其圈时作为提升证据，也不声称已复现两场冠军。
